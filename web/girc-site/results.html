Measured on Xiph.Org CIF · 12 sequences · 10 frames · QP 22–37

The mechanism saves 0.236% of the bitrate.

Twelve CIF sequences, ten frames each, four quantization parameters, and the inferred mode comes out 0.236% smaller than the explicit mode on the luma plane, and 0.149% smaller on the whole frame. It is smaller on eleven sequences of the twelve on the luma plane and ten on the whole frame.

The margin sweep below is the whole trade: the rate the encoder gives up in distortion, against the rate it saves in signalling.

How it was measured

Every figure is reproducible from the repository

GIRC runs in both signalling modes over a four-point QP sweep, and the Bjontegaard delta rate is computed by cubic polynomial interpolation over the overlapping PSNR range, as the JVET common test conditions define it. The two GIRC modes differ in exactly one thing: how the transform mode reaches the decoder.

The transform mode is VVC's, not an invention of this repository's: the plain DCT-II, or one of the four per-axis combinations of DCT-VIII and DST-VII that ITU-T H.266 defines as multiple transform selection. The explicit mode codes the mode the way the standard's mts_idx syntax does, which is what the decoder of a real codec would have to read.

The anchors are the real encoders: x265 for HEVC, SVT-AV1 for AV1 and VVenC 1.14.0 for VVC, each coding the same ten frames of the same file, all three planes, and measured by the same PSNR code. Every figure on this page is generated by tools/generate_figures.py from the committed benchmark report, so a figure cannot exist without the run behind it.

The predictor

Does the learned predictor earn its keep?

A claim about a trained predictor has to beat the alternative that needs no training and no model: always predict the plain DCT-II. The benchmark runs both over the same content, the same quantization parameters and the same margin, and reports them in the same file.

Predictor Mean BD-rate, luma Better on
Constant, always the plain DCT-II −0.120% 10 of 12
The shipped learned model −0.236% 11 of 12

The learned model is ahead on six of the twelve sequences, and the gap between the two is 0.116 percentage points of BD-rate, which is about half the mechanism's own effect. The model is one multinomial logistic regression over the joint mode, fitted on 570,240 real block records from the twelve sequences.

The honest reading

The joint mode is barely predictable: the ceiling of 50.65% is barely above the 50.10% majority class. The transform choice is driven by the block's own residual, which the decoder has not seen, and the geometry of the neighbourhood constrains it only weakly. The rate-distortion choice between the modes is close to a tie, so there is little for a predictor to predict.

These figures are lower than an earlier revision reported, and the reason is worth stating rather than hiding. An inter block carries a motion vector instead of an intra mode, so the decoder cannot know the mode the encoder would have chosen for it. A feature built from that mode let the encoder predict from information the decoder does not have, and the model trained on it looked better than it could ever be. The shipped code leaves the feature empty for an inter block, and the benchmark decodes every stream it encodes and refuses a result if the decoded picture differs from the encoder's own reconstruction.

Even so, the saving is 0.236%, not a headline number. The explicit signalling is already cheap for a context-adaptive coder to code, and the mechanism removes an overhead that is close to the distortion it costs to remove it. The margin sweep is the honest account of where that balance sits.

Intra and inter

The hypothesis holds, and the gain is smaller for inter

Inter prediction is implemented and measured. The inter blocks' mismatch rate is consistently lower than the intra blocks', so the hypothesis holds, but the gain over the majority baseline is smaller for the inter blocks than for the intra ones, because the inter blocks' transform distribution is more concentrated: there is less to gain when one mode already dominates.

The chroma planes

Why there are two rate axes

No chroma transform type is signalled: H.266 clause 7.3.9 codes a transform type for the luma plane, and the chroma transform type is inferred, and in 4:2:0 it is always the plain DCT-II. The reference encoder agrees — chroma transform selection is gated on m_useChromaTS, which is off by default and only enabled for 4:4:4. So the mechanism is a luma mechanism, exactly where the standard signals a transform type at all.

The chroma quantization parameter is mapped, not equal, through H.266's chroma quantization parameter mapping, checked against the reference implementation for every quantization parameter. The chroma grid is four by four chroma samples, one chroma block per luma block, and the chroma motion is derived from the luma motion as H.266 does.

What would change the answer

Where the number would move

A richer residual coder

The transform modes separate more when the residual coder is richer, so the rate-distortion choice between them stops being a tie and the predictor has something to find.

A larger transform set

The overhead the mechanism removes grows with the number of choices to signal and with how evenly they are distributed, so a codec with more transform types has more to save.

Signalling at a coarser grain

Signalling the transform once per region rather than once per block would make the prediction problem much easier and the overhead much larger.
